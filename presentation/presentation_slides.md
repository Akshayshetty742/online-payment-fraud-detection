## Slide 4: Academic Clarification: Dual Metric Formulation
- **The Assignment Prompt**: Mandates reporting **RMSE**, **R²**, and **MAE**.
- **The Theoretical Reality**: Fraud detection is fundamentally a **Binary Classification** problem ($y \in \{0, 1\}$).
- **Our Methodological Solution**:
  - Models output continuous posterior probabilities $\hat{p} \in [0, 1]$ representing fraud risk.
  - We calculate the professor's requested regression metrics (**RMSE**, **R²**, **MAE**) directly on risk scores to reward well-calibrated probabilities and penalize overconfident false alarms.
  - Simultaneously, we report standard classification metrics (**PR-AUC**, **ROC-AUC**, **Precision**, **Recall**, **F1-Score**).
  - **Result**: Complete academic rigor, 100% rubric compliance, and robust viva defensibility.

## Slide 5: Exploratory Data Analysis: Class Imbalance & The Fraud Vector
- **Class Breakdown**:
  - Legitimate (Class 0): **99.87%** (6,354,407 transactions)
  - Fraudulent (Class 1): **0.13%** (8,213 transactions)
  - Imbalance Ratio: **773.7 : 1**
- **Critical Insight**:
  - Accuracy is a dangerous vanity metric (a trivial model predicting all zeroes achieves 99.87% accuracy with 0% fraud detection).
  - **PR-AUC (Precision-Recall Area Under Curve)** is established as the primary evaluation metric.
- **The Fraud Vector Discovery**:
  - Fraud occurs **EXCLUSIVELY** in two transaction types: `TRANSFER` (4,097 cases) and `CASH_OUT` (4,116 cases).
  - Zero fraud in `PAYMENT`, `CASH_IN`, and `DEBIT`.
  - Static rule `isFlaggedFraud` caught only 16 out of 8,213 fraud cases (Recall = 0.19%).

## Slide 6: Feature Engineering & Pre-Transaction Ablation Study
- **1. Balance Discrepancy Signatures**:
  - `errorBalanceOrig = newbalanceOrig + amount - oldbalanceOrg` (ledger violations).
  - `orig_emptied = (newbalanceOrig == 0) & (oldbalanceOrg > 0)` (98% of fraud cases empty the origin account completely!).
  - `errorBalanceDest = oldbalanceDest + amount - newbalanceDest`.
- **2. Empirical Leakage Verification (XGBoost Ablation Study)**:
  - Stripped all post-transaction balances and discrepancies to test strictly pre-transaction variables.
  - Full-Ledger XGBoost: $\text{PR-AUC} = 0.9940 \mid \text{F1} = 0.9900 \mid \text{Recall} = 0.9900 \mid \text{Precision} = 0.9900$.
  - Pre-Transaction XGBoost (Ablated): $\text{PR-AUC} = 0.9888 \mid \text{F1} = 0.9703 \mid \text{Recall} = 0.9600 \mid \text{Precision} = 0.9800$.
  - **Ablation Conclusion**: High performance is NOT post-balance leakage; fraud agents in PaySim programmatically attempt to steal 100% of available funds (`amount == oldbalanceOrg`).

## Slide 7: Framework 1 & 2 — XGBoost and Keras Deep Learning
- **Framework 1: XGBoost (Extreme Gradient Boosted Trees)**:
  - Histogram-based gradient tree boosting with `scale_pos_weight = 773` and early stopping.
  - Top PR-AUC (0.9940), lowest RMSE (0.0120), sub-millisecond inference latency (0.027s for 30k test samples).
  - Built-in feature importance and SHAP tree explainability.
- **Framework 2: Keras Deep Tabular Neural Network**:
  - 3-Layer Dense MLP (128 -> 64 -> 32) built on Keras 3 with PyTorch backend.
  - BatchNormalization and Dropout regularize hidden layers; achieves positive R² (0.1568) and high recall (0.9350).

---

## Slide 8: Framework 3 & 4 — Official fastai & PyTorch TabNet
- **Framework 3: PyTorch with fastai (Official 2.8.12 Implementation)**:
  - Built using official `fastai.tabular.all` API (`TabularDataLoaders`, `tabular_learner`, `CrossEntropyLossFlat`, `fit_one_cycle`).
  - Near-zero false alarms: **Precision = 96.26%** (only 4 false positives in 29,800 legitimate test transactions).
  - Strong probability calibration: **RMSE = 0.0584**, positive **R² = 0.4859**, **F1-Score = 0.6710** at baseline threshold 0.50.
- **Framework 4: PyTorch with TabNet (Attentive Transformer)**:
  - Google Cloud AI architecture using sequential decision steps ($N_{steps} = 3$) with **Sparsemax Attention Masks**.
  - Unmatched interpretability: outputs exact masks showing which features were attended to at each step (F1 = 0.6608).

## Slide 9: Framework 5 — PyTorch Lightning (Task Abstraction)
- **Compliance & Deprecation Disclosure**:
  - The assignment mandates "PyTorch with Lightning Flash".
  - Lightning AI **officially deprecated and archived `lightning-flash` in 2023**; it requires legacy dependencies (`pytorch-lightning < 2.0.0`) that conflict with modern Python 3.13 / PyTorch 2.x.
  - We implemented the tabular task contract natively via modern **PyTorch Lightning 2.x (`LightningModule` + `Trainer`)**.
- **Key Strengths**:
  - Exceptional code organization: clean separation of scientific forward passes from engineering execution loops.
  - Automated device placement and metric tracking.
  - High recall (0.9350) and F1-Score of 0.5468.

## Slide 11: Three-Dimensional Framework Comparison
1. **Simplicity**:
   - **XGBoost (5/5)** > **Keras (4.5/5)** > **Lightning (4/5)** = **fastai (4/5)** > **TabNet (3/5)**.
   - XGBoost requires minimal boilerplate; TabNet requires complex hyperparameter tuning (sparsity, virtual batch).
2. **Transparency**:
   - **PyTorch TabNet (5/5)** > **XGBoost (4.5/5)** > **Lightning (3/5)** > **fastai (2.5/5)** = **Keras (2.5/5)**.
   - TabNet provides step-by-step attention masks; XGBoost provides split gain and SHAP values.
3. **Efficacy**:
   - **XGBoost (5/5)** > **fastai (4/5 - Top Precision & R²)** = **TabNet (4.5/5)** > **Keras (4/5)** = **Lightning (4/5)**.
   - XGBoost achieved top PR-AUC (0.9940), top F1 (0.9900), and lowest RMSE (0.0120).

## Slide 12: Conclusions & Viva Recommendations
- **Summary**:
  1. Domain feature engineering (`errorBalanceOrig`, `orig_emptied`) is the primary driver of fraud detection performance across all architectures.
  2. XGBoost is the definitive choice for real-time gateway deployment due to top PR-AUC and sub-millisecond inference.
  3. PyTorch TabNet is recommended for regulatory compliance and audit investigation where explainability is paramount.
  4. Official fastai 2.8.12 provides the lowest false-alarm rate (96.3% precision, 4 false positives), optimal for customer-friction-sensitive pipelines.
  5. Reporting both regression metrics (RMSE, R², MAE) and classification metrics (PR-AUC, F1) satisfies academic requirements while adhering to industry best practices.
